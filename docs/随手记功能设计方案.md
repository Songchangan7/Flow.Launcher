# 随手记功能设计方案

## 1. 目标

为 Flow Launcher 增加一个“随手记”能力，让用户在打开主输入框后，通过固定关键词快速进入记笔记模式，立即记录临时想法、待办事项和灵感内容。

这个功能的核心价值是：

- 进入快：不需要先打开独立笔记软件
- 记录轻：一句话即可保存
- 检索快：新建记录的同时也能搜到旧内容
- 心智清晰：显式进入“随手记模式”，不干扰普通搜索

## 2. 设计结论

推荐将“随手记”实现为一个独立的内置插件模式，而不是直接修改主输入框的全局搜索行为。

推荐入口方案：

- Action Keyword 使用 `n`
- 同时提供一个专属快捷键，用于唤起 Flow Launcher 并自动预填 `n `

这样可以同时兼顾：

- 高频使用时的输入效率
- 与现有 Flow Launcher 查询架构的兼容性
- 对普通全局搜索体验的最小影响

## 3. 为什么推荐 `n`

在当前架构下，查询是按“首个词是否精确匹配 Action Keyword”来分发的，而不是按前缀匹配。

因此：

- 输入 `n` 会进入随手记模式
- 输入 `n 今天整理方案` 会进入随手记模式
- 输入 `notion`、`node`、`new`、`npm` 不会进入随手记模式

这意味着 `n` 不会和“以 n 开头的普通搜索”发生冲突，只会在“首个完整词就是 n”时才触发。

## 4. 典型使用场景

### 场景 1：快速记录灵感

用户打开 Flow Launcher，输入：

```text
n 给插件系统增加轻量笔记能力
```

结果列表第一项显示：

- 保存这条笔记

用户回车后立即保存。

### 场景 2：边记边搜

用户输入：

```text
n chrome 标签搜索
```

结果列表同时显示：

- 保存“chrome 标签搜索”
- 已有笔记：Chrome 标签页搜索说明
- 已有笔记：tab 插件设计草案

用户可以决定新建，或者直接打开已有记录。

### 场景 3：查看最近记录

用户输入：

```text
n
```

结果列表显示：

- 最近笔记
- 置顶笔记
- 今天的记录
- 常用操作

## 5. 推荐交互设计

### 5.1 进入方式

- 输入 `n`
- 输入 `n 空格 + 内容`
- 使用专属快捷键直接打开并预填 `n `

推荐把“快捷键预填 `n `”作为高频入口，因为这会明显降低使用门槛。

### 5.2 结果列表行为

当输入为 `n` 时：

- 展示最近笔记
- 展示置顶笔记
- 展示“查看今天记录”“查看最近 20 条”等快捷操作

当输入为 `n 内容` 时：

- 第一条结果固定为“保存这条笔记”
- 下方展示与该内容相关的已有笔记
- 支持直接回车保存

### 5.3 保存后的行为

建议支持两种保存行为：

- 默认行为：保存后关闭窗口
- 可选行为：保存后保留窗口并继续记录

第一版建议默认采用“保存后关闭窗口”，保持简单直接。后续可以增加“连续记录模式”。

## 6. 数据模型建议

第一版建议采用最小可用模型：

- `Id`
- `Content`
- `CreatedAt`
- `UpdatedAt`
- `IsPinned`

第二阶段可扩展：

- `Tags`
- `Archived`
- `LastViewedAt`
- `Source`

## 7. 存储方案建议

第一版推荐使用本地 JSON 存储。

原因：

- 实现简单
- 易于调试
- 适合 MVP
- 数据量在早期通常不会大到需要数据库

当后续需求扩大，例如：

- 记录数量明显增长
- 需要更复杂的搜索
- 需要排序、过滤、统计能力

再切换为 SQLite 会更合适。

## 8. MVP 功能范围

第一版推荐只做以下能力：

- 支持通过 `n` 进入随手记模式
- 支持输入内容后直接保存
- 支持展示最近笔记
- 支持按关键词搜索已有笔记
- 支持复制笔记内容
- 支持编辑笔记
- 支持删除笔记
- 支持置顶笔记

这版已经足够支撑“平时记笔记”和“快速记录灵感”的核心用途。

## 9. 后续增强方向

在 MVP 验证通过后，可以逐步增加：

- 多行编辑窗口
- 标签系统
- 按日期分组
- 今天记录 / 本周记录视图
- Markdown 导出
- 文本导入
- 连续记录模式
- 固定模板插入
- AI 总结最近笔记

## 10. 不推荐的方案

不推荐把随手记设计成“普通输入自动识别是否应该记笔记”。

原因：

- 会干扰主搜索框的通用搜索行为
- 用户不容易理解当前是在搜索还是在记录
- 会提升误触概率
- 与 Flow Launcher 现有的关键词路由机制不一致

显式关键词模式更符合 Flow Launcher 的产品心智，也更容易维护。

## 11. 最终推荐

推荐采用以下方案作为第一版：

- 将随手记实现为独立内置插件
- Action Keyword 使用 `n`
- 提供专属快捷键并预填 `n `
- `n` 显示最近记录与快捷操作
- `n 内容` 默认提供“保存这条笔记”
- 同时显示匹配的历史笔记
- 本地使用 JSON 保存数据

这个方案在输入效率、实现复杂度、可扩展性和对现有架构的兼容性之间，整体最均衡。

## 12. 逐阶段实现方案

为了降低一次性实现的复杂度，建议将“随手记”拆成多个阶段推进。每一阶段都应形成可以独立验证和交付的结果。

### 阶段 1：最小可用版本

目标：

- 先让用户能够稳定进入随手记模式
- 先完成“快速记录”这一核心价值

实现范围：

- 新增独立内置插件
- 配置 Action Keyword 为 `n`
- 支持输入 `n 内容` 后直接保存笔记
- 支持输入 `n` 时显示最近笔记
- 使用本地 JSON 文件保存数据
- 每条记录保存 `Id`、`Content`、`CreatedAt`、`UpdatedAt`、`IsPinned`

这一阶段不做：

- 多行编辑窗口
- 标签系统
- 复杂筛选
- 导入导出

完成标志：

- 用户可以通过 `n` 进入模式
- 用户可以回车保存一条新笔记
- 重新打开后可以看到最近记录

### 阶段 2：新建与检索并行

目标：

- 提升“记过的内容能立刻找回”的使用价值
- 避免重复记录

实现范围：

- 当输入 `n 内容` 时，第一条结果固定显示“保存这条笔记”
- 同时根据输入内容搜索历史笔记
- 历史笔记结果支持打开查看和复制内容
- 对最近记录和命中记录进行基础排序

这一阶段的重点：

- 一次输入同时支持“新建”和“查旧”
- 让“边记边搜”的产品心智真正成立

完成标志：

- 用户输入新内容时，既能保存，也能立刻看到相关旧笔记
- 历史记录搜索结果具有基本可用性

### 阶段 3：基础管理能力

目标：

- 让随手记从“能记”升级到“能管理”

实现范围：

- 支持编辑笔记
- 支持删除笔记
- 支持置顶笔记
- 支持复制笔记内容
- 支持查看今天记录和最近若干条记录

这一阶段的重点：

- 补齐日常维护笔记所需的核心操作
- 提高用户长期使用意愿

完成标志：

- 用户不需要离开 Flow Launcher，也能完成常用的笔记整理动作

### 阶段 4：增强录入体验

目标：

- 适配更长内容和更复杂的记录场景

实现范围：

- 增加多行编辑窗口
- 支持从结果中进入编辑态
- 增加“保存并继续记录”能力
- 允许用户配置保存后的默认行为

这一阶段的重点：

- 解决单行输入框不适合长内容编辑的问题
- 提高连续记录效率

完成标志：

- 用户既可以快速记一句话，也可以顺畅记录较长内容

### 阶段 5：结构化与归档能力

目标：

- 让笔记从“临时记录”逐步演进为“可整理的信息池”

实现范围：

- 支持标签
- 支持归档
- 支持按日期分组
- 支持“今天”“本周”“置顶”视图
- 支持简单筛选与排序

这一阶段的重点：

- 提升信息组织能力
- 让记录不只是堆积，而是可以被重新利用

完成标志：

- 用户可以按主题、时间或状态管理自己的随手记内容

### 阶段 6：导入导出与扩展能力

目标：

- 提升数据可迁移性和生态扩展能力

实现范围：

- 支持导出为 `txt` 或 `md`
- 支持导入已有文本内容
- 评估是否从 JSON 升级到 SQLite
- 为后续 AI 总结、模板插入等能力预留数据结构

这一阶段的重点：

- 降低数据锁定风险
- 为后续高级能力铺路

完成标志：

- 用户的记录可以方便备份、迁移和再利用

## 13. 推荐实施顺序

如果希望尽快上线并验证价值，推荐按下面顺序推进：

1. 阶段 1：最小可用版本
2. 阶段 2：新建与检索并行
3. 阶段 3：基础管理能力
4. 阶段 4：增强录入体验
5. 阶段 5：结构化与归档能力
6. 阶段 6：导入导出与扩展能力

其中，阶段 1 到阶段 3 已经足够构成一个可长期使用的第一版产品。后续阶段主要用于提升体验和扩展性。
