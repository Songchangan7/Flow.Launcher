# 随手记截图 / 图片附件设计方案

> 文档日期：2026-07-28  
> 范围：Quick Note 插件（`Creta.Plugin.Note`）  
> 关联文档：[随手记功能设计方案](随手记功能设计方案.md)、[随手记 SQLite 存储评估](随手记SQLite存储评估.md)  
> 结论：**支持截图与图片笔记；采用旁路附件目录 + 剪贴板粘贴优先，暂不把图片写入 JSON，也不立刻迁移 SQLite。**

## 1. 背景与问题

当前随手记只支持纯文本：

- `NoteItem.Content` 为字符串，持久化在 `notes.json`
- 编辑器为普通 `TextBox`
- 主输入框粘贴仅处理 Unicode 文本，且会去掉换行
- 插件不读取剪贴板中的 Bitmap / PNG / FileDrop

用户在「快速记一句话」之外，还有高频场景：**截图后立刻落成一条随手记**（方案讨论、报错界面、灵感草图等）。现有模型无法承载该诉求。

## 2. 设计目标

- **随手**：截图后尽量少步骤即可保存（优先复用系统截图 + 剪贴板）
- **不破坏文本体验**：纯文本笔记路径保持不变
- **存储可持续**：图片不塞进 `notes.json`，避免文件膨胀与备份困难
- **可迁移**：自定义笔记库路径时，附件与 JSON 一并移动
- **可演进**：为后续 OCR、多图笔记、SQLite 迁移预留字段，但不提前做重方案

## 3. 设计结论（推荐方案）

**旁路附件 + 剪贴板粘贴优先。**

| 决策 | 选择 |
|------|------|
| 图片存放 | 笔记库旁的 `attachments/` 目录，按笔记 ID 分子目录 |
| 元数据 | `NoteItem` 增加可选 `Attachments` 列表，JSON 只存引用 |
| 正文 | `Content` 可为空，或写一句说明 / 后续 OCR 文本 |
| 录入主路径 | 系统截图（如 Win+Shift+S）→ 剪贴板 → 编辑器 Ctrl+V 或主窗口 `n` 一键保存 |
| 不自研截屏 | 第一版不做 Creta 内置区域截屏工具 |
| 存储引擎 | 继续 JSON + 旁路文件；附件落地后再按 SQLite 评估文档的触发条件决定是否迁移 |

## 4. 为何推荐该方案

### 4.1 与现有架构对齐

随手记定位是本地、键盘优先、轻量插件。旁路附件不改变「单文件笔记库」心智，只需约定「笔记库 = `notes.json` + `attachments/`」。

### 4.2 避开高成本路线

| 备选方案 | 主要问题 | 结论 |
|----------|----------|------|
| Base64 写入 `notes.json` | 体积暴涨，导入导出与备份变差 | 否决 |
| 立刻迁 SQLite + BLOB | 成本高；现有评估将「附件」列为触发条件之一，宜先验证产品价值 | 暂缓 |
| 只存绝对路径、不拷贝文件 | 临时目录 / 桌面文件易丢，笔记不可迁移 | 否决 |
| 内置截屏工具 | 与「粘贴即记」重复，权限与实现成本高 | 第一版不做 |

### 4.3 与 SQLite 评估的关系

[随手记 SQLite 存储评估](随手记SQLite存储评估.md) 将「附件」列为重新评估触发条件之一。本方案用旁路目录先落地附件能力：

- 若图片笔记用量小、检索仍以说明文字 + 标签为主 → 继续 JSON 即可
- 若出现大规模附件、OCR 全文检索、多表关联等 → 再启动 SQLite 方案设计

## 5. 数据模型

### 5.1 附件项

```csharp
public sealed class NoteAttachment
{
    public string Id { get; set; } = string.Empty;           // 附件唯一 ID
    public string FileName { get; set; } = string.Empty;     // 展示名，如 screenshot.png
    public string RelativePath { get; set; } = string.Empty; // 相对笔记库目录，如 attachments/{noteId}/{id}.png
    public string MimeType { get; set; } = "image/png";
    public int? Width { get; set; }
    public int? Height { get; set; }
    public long? ByteSize { get; set; }
    public DateTime CreatedAt { get; set; }
    public string Source { get; set; } = string.Empty;       // clipboard / file / import
}
```

### 5.2 笔记扩展

在现有 `NoteItem` 上增加：

```csharp
public List<NoteAttachment> Attachments { get; set; } = [];
```

兼容策略：

- 旧版 `notes.json` 无 `Attachments` 时按空列表加载
- 写入时若附件为空，可用 `JsonIgnoreCondition.WhenWritingDefault` 省略字段，减少噪音
- `Content` 仍为主要可搜索字段；纯图笔记允许 `Content` 为空

### 5.3 磁盘布局

相对笔记库根目录（`notes.json` 所在目录）：

```text
notes.json
attachments/
  {noteId}/
    {attachmentId}.png
```

规则：

- 删除笔记 → 删除对应 `attachments/{noteId}/`
- 删除单个附件 → 删除文件并更新 `Attachments` 列表
- 自定义 `NotesFilePath` 切换时：迁移 / 合并 JSON 的同时迁移 `attachments/`（按笔记 ID 合并，冲突策略与现有笔记 ID 合并一致）

## 6. 录入路径

按优先级：

| 优先级 | 入口 | 行为 |
|--------|------|------|
| **P0** | 笔记编辑器 / 管理页 **Ctrl+V** | 剪贴板含图片 → 写入附件并刷新缩略图；可同时保留文字说明 |
| **P0** | 主窗口 `n`，剪贴板有图，且查询为空或仅空白 | 结果首条「保存剪贴板图片」；回车落库、轻提示、关闭窗口（与现有保存文本对称） |
| P1 | 编辑器「添加图片」/ 拖入文件 | 覆盖非截图场景（相册、导出图等） |
| P2 | 系统截图工具后粘贴 | 不自研截屏，明确文档引导使用 Win+Shift+S 等 |

主窗口粘贴注意：

- 仅在 **随手记模式**（Action Keyword `n`）下识别剪贴板图片，避免干扰全局搜索粘贴去换行逻辑
- 若同时存在文本与图片：优先按产品约定处理（推荐：图片落附件，文本写入 `Content`；若仅有图片则 `Content` 为空）

## 7. 展示与交互

### 7.1 启动器结果列表

- 有附件时：标题旁显示图片标识，或展示小缩略图（若性能可接受）
- `Content` 非空：展示摘要；为空：展示「图片笔记」及附件张数 / 时间
- 回车默认行为：有说明文字时复制文本；纯图笔记可改为打开编辑器预览，或复制图片到剪贴板（实现阶段二选一，推荐 **打开预览**）

### 7.2 编辑器

- 正文上方或侧方为附件缩略图区
- 支持：粘贴添加、删除附件、另存为、点击放大
- 第一版单笔记建议上限见第 8 节

### 7.3 笔记管理页

- 列表增加「含附件」列或图标
- 双击进入编辑器查看图片
- 批量删除时同步清理附件目录

### 7.4 检索（第一版）

- 依赖 `Content`、标签、时间视图
- **不做** OCR 全文检索；列为后续增强（更接近 SQLite / FTS 触发条件）

## 8. 体积与格式约束

建议默认值（可配置或常量）：

| 项 | 建议 |
|----|------|
| 存储格式 | 统一转 PNG，或保留原格式并记录 `MimeType` |
| 单图大小上限 | 5–10 MB，超出拒绝并提示 |
| 单笔记附件数 | ≤ 5 |
| 可选缩放 | 宽边超过阈值（如 2560）则缩小后再存 |
| 允许类型 | `image/png`、`image/jpeg`、`image/bmp`、`image/gif`（第一版可先 PNG/JPEG） |

## 9. 导入导出

| 能力 | 行为 |
|------|------|
| 备份 notes.json | 保持现有；额外提示「含图片时请一并备份 attachments 目录」 |
| 导出 TXT/MD | 正文导出；图片可用相对链接指向 `attachments/...`，或导出包内附带图片 |
| 导出「完整备份」 | 推荐新增：打包 `notes.json` + `attachments/`（zip） |
| 导入 JSON | 合并笔记元数据；若导入包含附件目录则按相对路径拷贝 |

## 10. 分阶段落地

### 阶段 A：模型与编辑器粘贴（MVP）

- `NoteAttachment` + `NoteItem.Attachments`
- 旁路目录读写、删除联动
- 编辑器 Ctrl+V 存图、缩略图预览与删除
- 仓储测试覆盖：保存、删除、路径迁移骨架

### 阶段 B：主窗口一键保存（核心体验）

- `n` + 剪贴板图片 →「保存剪贴板图片」
- 保存后轻提示并关闭
- 结果列表对纯图笔记的展示文案

### 阶段 C：管理与备份

- 管理页附件标识
- 完整备份（JSON + attachments）
- 导入导出含附件的规则落地

### 阶段 D：可选增强

- OCR 写入 / 补充 `Content`，支持按图内文字搜索
- 多图笔记体验打磨、拖拽排序
- 按 [SQLite 评估](随手记SQLite存储评估.md) 触发条件决定是否迁移存储引擎

## 11. 涉及模块（实现指引）

| 模块 | 预期改动 |
|------|----------|
| `NoteItem` / 新建 `NoteAttachment` | 模型扩展 |
| `NoteRepository` | 附件路径解析、读写、删除、迁移 |
| `NoteEditorWindow` | 粘贴、缩略图、删除附件 |
| `Main.cs` / 结果构建 | 剪贴板检测、保存图片结果项 |
| 宿主粘贴逻辑 | 仅在 `n` 模式或编辑器内处理图片，避免破坏全局粘贴 |
| 导入导出 / 管理页 | 阶段 C |
| 测试 | 仓储与迁移；可选剪贴板相关 UI 测 |

## 12. 风险与边界

- **磁盘占用**：需上限与可选压缩，并在设置或文档中说明附件目录位置
- **路径切换**：必须随 `NotesFilePath` 迁移，否则会出现「笔记在、图丢了」
- **隐私**：截图可能含敏感信息；保持纯本地，不做云上传
- **性能**：结果列表避免同步解码大图；缩略图可缓存或限制尺寸
- **空 Content**：搜索与去重逻辑需允许「无正文但有附件」的笔记，避免被当成无效条跳过

## 13. 非目标（第一版明确不做）

- Creta 内置区域 / 窗口截屏工具
- 将图片 Base64 写入 `notes.json`
- OCR 与图片语义搜索
- 云同步、多设备附件冲突解决
- 视频、PDF 等非图片附件类型

## 14. 验收标准（阶段 A + B）

1. 系统截图后，在笔记编辑器 Ctrl+V，可看到缩略图且重启后仍在  
2. 对应文件出现在 `attachments/{noteId}/` 下，`notes.json` 中仅有引用字段  
3. 主窗口进入 `n` 且剪贴板有图时，回车可保存图片笔记并提示成功  
4. 删除该笔记后，附件目录被清理  
5. 纯文本 `n 内容` 保存路径行为与现网一致、无回归  

## 15. 总结

截图能力**可行且值得做**。推荐以「系统截图 → 剪贴板 → 随手记粘贴 / `n` 一键保存」为主路径，图片落在 `attachments/`，JSON 只存引用。先完成阶段 A/B 打通核心体验，再视用量决定 OCR 与是否迁 SQLite。
